# v0.3.1 — 管理登入、私密檔案及監控資源修補

## 修正內容

- AdGuard Home 管理介面要求原生帳戶登入；重新安裝及 runtime 更新保留現有帳戶與 BCrypt 密碼雜湊。新裝或舊有空帳戶設定以 `admin` 及當時的 `DNSCOMPLEX_WEB_PASSWORD` 初始化，其後分開管理。
- 初始 AdGuard 密碼須為 8–72 UTF-8 bytes；不適用的初始密碼會在寫入管理設定前拒絕。已有 AdGuard 帳戶時，不額外限制獨立的管理網頁密碼。
- 含有憑證的設定及 Xray 暫存檔從建立起使用私人權限；以原子替換發佈，失敗時保留原檔並清理暫存檔。
- metrics HTTP 及管理頁面改讀私人快照，避免每個請求觸發昂貴的主機檢查。收集程序使用跨程序鎖、30 秒總期限、8 MiB 輸出上限及子程序清理。
- metrics HTTP 同時處理最多 16 個請求，輸入總期限為 15 秒。缺少、無效或超過 60 秒的快照回報不可用；不完整收集使 `/healthz` 失敗，fresh `degraded` 狀態維持相容行為。
- 採樣 timer 在上一輪完成後 15 秒再次執行；systemd 採樣服務有 45 秒上限，避免慢樣本中止後續更新。

## 相容性及升級

- 保留 LAN HTTP 管理、SOCKS 及既有 VPN 管理路徑，沒有加入內部 CA 要求。HTTP 在 VPN 出口之後的 LAN 段仍是明文；本版沒有加入傳輸加密。
- 保留既有核心版本、域名分流和出口設定的設計；發佈 release 不會自動更新運行中的主機。完整 installer 仍可能更新核心及網路設定，升級前應備份並核對 dry-run 輸出。
- Debian 安裝相依套件新增 `python3-bcrypt` 及 `python3-yaml`。既有帳戶使用較長 web 密碼時，會在維護鎖內先補齊缺少的 YAML parser，再檢查帳戶；不會在檢查前寫入管理設定。本機 dry-run 須先準備 PyYAML 及 bcrypt。
- 若需手動改 AdGuard 設定，先停止服務，並確認監督服務不會立即將它重新拉起；修改後重啟並驗證登入。不要以線上工具產生密碼雜湊或將密碼放入命令列。
- 不包含 XSS 調查或修正，沒有對該疑點作出安全結論。

## 驗證範圍

- 發佈候選執行 installer contract（含 runtime reliability）及 README 列出的 Web 生命週期、HTTP contract、soak 資源限制回歸。
- 新增登入保留、初始密碼、私密檔案建立／失敗清理、metrics 快照與 HTTP／程序資源邊界測試。
- 對應功能版本已在 Debian 實機驗證：AdGuard 與管理 API 匿名請求被拒絕、正確登入成功；經 VPN 出口主機及 SOCKS 的相同路徑通過；真實 systemd timer 持續產生完整快照，最終 DNS／健康檢查正常。
- 實機功能版本與本 release 的差異包含版本標記、公開文件及缺少 YAML 套件時的安裝前檢查修補；不宣稱兩者檔案雜湊相同。缺套件的修補以隔離測試模擬套件管理邊界，再執行真實 parser／helper，沒有在生產機卸載套件重試。沒有從外部終端重新建立 VPN 連線，也沒有在生產機進行資源耗盡或斷電測試。
